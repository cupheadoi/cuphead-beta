# CupHead — پلتفرم المپیاد کامپیوتر و تفکر الگوریتمی

پلتفرم جامع یادگیری المپیاد کامپیوتر، برنامه‌نویسی الگوریتمی، سی‌شارپ/سی‌پلاس‌پلاس، تئوری و ترکیبیات به همراه نقشه راه تعاملی، سیستم مشارکت جامعه و کتابخانه مسائل مسابقات معتبر (USACO، CSES، المپیاد ایران، Codeforces و...).

---

## ۱. معماری پایگاه‌داده و ماندگاری اطلاعات (Database Architecture)

پایگاه‌داده این پروژه از ابتدا بر پایه **SQLite 3** طراحی شده است:
- فایل اصلی دیتابیس: `server/data/cuphead.sqlite`
- تمام جداول، اندیس‌ها، روابط، کلیدهای خارجی و تنظیمات به صورت تک‌فایل و کاملاً پرتابل نگهداری می‌شوند.
- در سیستم دو حالت کاری هوشمند برای سازگاری با هر دو محیط **Vercel** و **سرور شخصی (VPS / Docker)** تعبیه شده است:
  1. **حالت ابری خودکار روی Vercel (با استفاده از Vercel Blob):** برای پایداری ۱۰۰٪ اطلاعات کاربران و عدم حذف داده‌ها هنگام دیپلوی‌های مجدد گیت‌هاب.
  2. **حالت محلی استاندارد SQLite:** برای اجرا روی سرورهای اختصاصی، مجازی (VPS)، هاست‌های لینوکسی، داکر و ماشین محلی بدون نیاز به هیچ سرویس ابری یا هزینه اضافی.

---

## ۲. فعال‌سازی ماندگاری دائمی روی Vercel (بدون از دست رفتن داده‌ها در Redeploy)

### چرا ورسل داده‌های SQLite محلی را ریست می‌کند؟
سرویس Vercel بر پایه معماری Serverless (توابع بدون سرور) کار می‌کند و هارد دیسک دائمی ندارد؛ فایل‌های موقت در پوشه `/tmp` با هر بار به خواب رفتن کانتینر یا هر بار دیپلوی جدید از گیت‌هاب ریست می‌شوند.

### راهکار دائمی ورسل با Vercel Blob (تنظیم در ۱ دقیقه):
سیستم به ماژول همگام‌ساز خودکار `@vercel/blob` مجهز شده است. برای فعال‌سازی:

1. وارد داشبورد پروژه خود در **[Vercel](https://vercel.com)** شوید.
2. به زبانه **Storage** بروید.
3. دکمه **Create Database** را زده و گزینه **Blob** را انتخاب کنید.
4. آن را به پروژه سایت خود متصل (Connect) کنید.
5. ورسل به‌صورت خودکار متغیر محیطی زیر را به پروژه شما اضافه می‌کند:
   ```env
   BLOB_READ_WRITE_TOKEN=vercel_blob_rw_...
   ```
6. **تمام!** از این لحظه به بعد:
   - با هر بار استارت کانتینر ورسل، آخرین دیتابیس از مخزن ابری Vercel Blob خوانده می‌شود.
   - هر تغییر (ثبت‌نام کاربر، ارسال راه‌حل، ایجاد درس یا تغییر نقش) بلافاصله روی مخزن ابری آپلود و ذخیره می‌گردد.
   - **هر چند بار که سورس‌کد را از گیت‌هاب در ورسل Redeploy کنید، داده‌ها هرگز پاک نخواهند شد.**

## ۳. راهنمای سوییچ به دیتابیس محلی SQLite (Switching to Pure Local SQLite)

اگر در آینده تصمیم گرفتید پروژه را از Vercel خارج کرده و روی **سرور اختصاصی، سرور مجازی (VPS)، هاست لینوکسی، داکر یا لوکال** اجرا کنید، انتقال با کمترین زحمت و در چند دقیقه انجام می‌شود:

### مراحل گام‌به‌گام انتقال به سرور اختصاصی:

#### گام ۱: دانلود آخرین نسخه دیتابیس از پنل مدیریت
1. با حساب مدیر یا Headmaster وارد پنل ادمین سایت شوید (`/admin`).
2. به بخش **«پایگاه‌داده و پشتیبان»** بروید.
3. روی دکمه **«دانلود آنی فایل پایگاه‌داده (.sqlite)»** کلیک کنید تا فایل کامل `cuphead-backup-...sqlite` دانلود شود.
*(همچنین این فایل مستقیماً روی سرور در مسیر `server/data/cuphead.sqlite` موجود است).*

#### گام ۲: دریافت کد و نصب روی سرور اختصاصی
روی سرور لینوکسی یا VPS خود:
```bash
# دریافت سورس کد از گیت‌هاب
git clone <آدرس_مخزن_شما>
cd cuphead

# نصب وابستگی‌ها و بیلد فرانت‌اند
npm install
npm run build
```

#### گام ۳: قرار دادن فایل دیتابیس دانلود شده
فایل `.sqlite` دانلود شده از گام ۱ را به عنوان `cuphead.sqlite` در مسیر پروژه قرار دهید:
```bash
cp /path/to/cuphead-backup.sqlite server/data/cuphead.sqlite
```

#### گام ۴: اطمینان از حالت Pure SQLite
برای اینکه سرور ۱۰۰٪ از دیتابیس محلی هارد دیسک شما استفاده کند:
- کافیست در فایل `.env` سرورتان متغیر `BLOB_READ_WRITE_TOKEN` را **تعریف نکنید (خالی بگذارید)**.
- سیستم به صورت کاملاً خودکار تشخیص می‌دهد که هیچ کلید ابری وجود ندارد و تمام درخواست‌ها را مستقیماً روی فایل محلی SQLite اجرا می‌کند.

#### گام ۵ (بسیار مهم): ایمن‌سازی دیتابیس در برابر Git Pull های بعدی
اگر دیتابیس درون همان پوشه پروژه باشد، ممکن است هنگام اجرای `git pull` برای آپدیت‌های آینده با تغییرات گیت تداخل پیدا کند. برای حل دائمی این موضوع:
1. یک پوشه امن خارج از سورس‌کد بسازید:
   ```bash
   mkdir -p /var/cuphead-data
   cp server/data/cuphead.sqlite /var/cuphead-data/cuphead.sqlite
   ```
2. در فایل `.env` سرور این متغیر را ست کنید:
   ```env
   DATABASE_PATH=/var/cuphead-data/cuphead.sqlite
   ```
از این لحظه به بعد، هر بار که با دستور `git pull origin main` کد سایت را از گیت‌هاب آپدیت کنید، **پایگاه‌داده کاربران و محتوا کاملاً محفوظ، دست‌نخورده و مستقل باقی می‌ماند.**

#### گام ۶: اجرای مداوم سرور با PM2
```bash
# نصب ابزار اجرای دائمی سرویس‌ها
npm install -g pm2

# راه‌اندازی سرور
pm2 start server/server.js --name "cuphead"

# تنظیم اجرای خودکار با روشن‌شدن سرور
pm2 startup
pm2 save
```

## ۴. جدول متغیرهای محیطی (Environment Variables)

| نام متغیر | اجباری؟ | کاربرد |
| :--- | :---: | :--- |
| `SESSION_SECRET` | توصیه می‌شود | کلید امنیتی برای امضای توکن‌های ورود کاربران و ادمین‌ها |
| `BLOB_READ_WRITE_TOKEN` | اختیاری (مخصوص Vercel) | کلید دسترسی به Vercel Blob برای ماندگاری ابری خودکار روی ورسل. در صورت خالی بودن، دیتابیس کاملاً محلی SQLite خواهد بود. |
| `DATABASE_PATH` | اختیاری (مخصوص VPS) | مسیر اختصاصی ذخیره‌سازی فایل `.sqlite` خارج از پوشه Git (مانند `/var/data/cuphead.sqlite`) |
